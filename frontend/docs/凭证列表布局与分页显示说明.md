# 凭证列表布局与分页显示说明

## 一、问题描述

凭证列表页面在「合并头部与查询区域」并优化布局后，出现以下现象：

1. **分页不显示**：表格区域占满视口，分页组件被挤出屏幕下方，需要滚动页面才能看到。
2. **超出屏幕高度**：整体内容高度超过当前窗口高度，导致分页因屏幕高度限制始终在可视范围之外。
3. **表格内部滚动条不生效**：表格有固定高度、行数较多时，纵向滚动条可见，但滚轮滚动、拖拽滚动条均无法滚动表体。

用户期望：**头部、表格、分页在同一屏内完整展示，无需整页滚动；表格内容多时仅在表格内部滚动，分页始终固定在底部可见。**

---

## 二、原因分析

### 2.1 布局层级关系

页面实际渲染层级为：

```
.home-container (height: 100vh)
  └── .content-container (flex: 1)
        └── .main-container (flex: 1, flex column)
              ├── .main-tabs (tab 栏，固定高度)
              └── .tab-content (flex: 1)          ← 列表页的父容器
                    └── 路由组件根节点
                          └── .voucher-list       ← 凭证列表根节点
                                ├── .header-filter-area
                                ├── .table-area
                                └── .pagination-area
```

### 2.2 问题根源

| 问题 | 原因 |
|------|------|
| 分页被挤出视口 | 列表使用 `height: calc(100vh - 60px)` 等固定计算，未与父级 `.tab-content` 的实际可用高度对齐；且表格区域使用 `flex: 1` 时未配合 `min-height: 0`，在 flex 布局中会按内容撑开，把分页顶到下方。 |
| 整页滚动 | 列表容器未设置 `overflow: hidden`，或父级存在 `overflow: auto`，导致整页出现滚动条，分页随内容一起被滚走。 |
| 高度计算不准 | 表格高度用 `window.innerHeight - 固定值` 估算，未考虑顶栏、tab 栏、padding 等，在不同分辨率或不同父容器下容易偏差，表格区域仍可能占满或溢出。 |

核心结论：**要让分页始终在视口内，必须让「列表容器高度 = 父级提供的可用高度」，且内部采用「头部固定 + 表格占剩余空间并内部滚动 + 分页固定」的 flex 分配，而不是由内容总高度决定整页高度。**

### 2.3 表格内部滚动不生效的原因

Element Plus 表格的 DOM 结构为：`body-wrapper` 内包了一层 **el-scrollbar**，真正可滚动的元素是 **`.el-scrollbar__wrap`**（滚轮、拖拽都应作用在 wrap 上）。

| 现象 | 原因 |
|------|------|
| 滚动条可见但拖不动、滚轮无效 | 对 `.el-table` 使用 `flex: 1`、`display: flex` 等，让表格根参与 flex 分配；在 flex 子项上容易与组件内联的 `height` 共同作用，导致内部 **100% 高度链** 断裂。 |
| 高度链断裂 | `body-wrapper` → `el-scrollbar` → **wrap** 的 100% 高度依赖父级有明确高度；若表格根被 flex 拉伸或计算异常，wrap 得不到有限高度，出现 `scrollHeight === clientHeight`，无法产生有效滚动。 |
| 滚轮不生效 | 表格的 `handleFixedMousewheel` 使用 `bodyWrapper.scrollTop`，而实际可滚动的是 **wrap**；若 wrap 未成为唯一滚动容器或事件未作用在 wrap 上，滚轮无效。 |

结论：**要让表格内部正常滚动，必须保证「表格根元素有明确高度」且「高度通过 100% 完整传递到 `.el-scrollbar__wrap`」，不在表格根上做会破坏高度链的 flex 覆盖；滚动只发生在 wrap 上。**

---

## 三、解决思路

### 3.1 整体策略

1. **高度继承**：列表根节点使用 `height: 100%`，占满父级（tab 内容区）给出的高度，不自行使用 `100vh` 等与视口直接换算，避免与真实布局不一致。
2. **父级传递高度**：在 HomeView 中为 `.tab-content` 及其直接子节点（路由出口）设置 flex 与 `min-height: 0`，保证「可用高度」能传递到列表根节点。
3. **内部三分区布局**：列表内部使用 flex 纵向布局，三块区域分别为「头部固定」「表格自适应剩余高度」「分页固定」，只有表格区域可滚动。
4. **禁止整页滚动**：列表根节点设置 `overflow: hidden`，避免列表内部再产生整页滚动条；滚动只发生在表格的 `el-table` 内部。
5. **表格高度可测**：表格高度基于「列表容器实际高度」动态计算（容器 ref + clientHeight），而不是用 `window.innerHeight` 估算，保证与真实可用高度一致。

### 3.2 布局结构（目标）

```
.voucher-list (height: 100%, min-height: 0, overflow: hidden, flex column)
├── .header-filter-area   (flex: 0 0 auto)   ← 固定高度，不参与伸缩
├── .table-area           (flex: 1 1 0, min-height: 0, overflow: hidden)  ← 占满剩余空间
│   └── .table-area-inner (flex: 1 1 0, min-height: 0, height: 100%)     ← 内层固定高度，避免对 el-table 做 flex
│         └── el-table    (:height="100%")   ← 表格内部 100% 传到 el-scrollbar__wrap，仅 wrap 滚动
└── .pagination-area      (flex: 0 0 auto)   ← 固定高度，始终在视口内
```

要点：

- **flex: 1 1 0**：表格区域「伸缩占满剩余空间」，`flex-basis: 0` 表示从 0 开始分配，避免被内容撑高。
- **min-height: 0**：在 flex 子项上必须设置，否则子项默认 `min-height: auto` 会按内容高度计算，无法被压缩，导致分页被顶出视口。
- **overflow: hidden**：列表根节点和表格区域都需设置，确保只有表格内部出现滚动条。

### 3.3 表格内部滚动的正确实现

1. **不直接对 `.el-table` 做 flex 拉伸**：表格根元素高度应由「父容器 100%」或组件传入的固定高度决定，避免用 `flex: 1` 等覆盖导致内部 100% 链断裂。
2. **增加内层固定高度容器**：在 `.table-area` 内增加一层 `.table-area-inner`，用 `flex: 1 1 0`、`min-height: 0`、`height: 100%` 从表格区域拿到明确高度；**表格放在该内层里**，不再让 `.el-table` 直接作为 `.table-area` 的 flex 子项。
3. **表格用 100% 占满内层**：`el-table` 使用 `:height="'100%'"`，表格根元素高度完全由内层容器决定，内部 body-wrapper → el-scrollbar → **wrap** 的 100% 能正确传递，wrap 获得有限高度，成为唯一可滚区域。
4. **保证 wrap 为唯一滚动容器**：对 `.el-scrollbar__wrap` 明确设置 `height/max-height: 100%`、`overflow-y: auto !important`、`overflow-x: auto !important`，必要时加 `touch-action: pan-y pan-x`，确保滚轮与拖拽都作用在 wrap 上。

## 四、具体实现要点

### 4.1 凭证列表页（VoucherList.vue）

- **根节点**
  - `height: 100%`、`min-height: 0`、`overflow: hidden`，并增加 `ref="voucherListRef"` 用于高度计算。
- **头部**
  - `flex: 0 0 auto`，适当减小 padding，保证固定、紧凑。
- **表格区域**
  - `flex: 1 1 0`、`min-height: 0`、`overflow: hidden`。
  - **内层容器**：增加 `.table-area-inner`（`flex: 1 1 0`、`min-height: 0`、`height: 100%`），避免对 `.el-table` 直接做 flex 导致内部 100% 高度链断裂。
  - **表格高度**：`el-table` 使用 `:height="'100%'"` 填满内层，使 body-wrapper → el-scrollbar → `.el-scrollbar__wrap` 的 100% 链完整，wrap 成为唯一可滚区域；不再对 `.el-table` 设置 `flex: 1` 等覆盖。
  - **内部滚动**：`.el-table__body-wrapper` 保持 `overflow: hidden`；对 `.el-scrollbar__wrap` 设置 `height/max-height: 100%`、`overflow-y: auto !important`、`overflow-x: auto !important`、`touch-action: pan-y pan-x`，保证滚轮与拖拽滚动条均生效。
- **分页区域**
  - `flex: 0 0 auto`、固定 `min-height`（如 44px），保证始终在底部且可见。
- **表格高度计算**（若改用 100% 方案则可不依赖该数值）
  - 使用 `voucherListRef.value.clientHeight` 作为「整体高度」，再减去头部、分页、容器 padding、表格 padding/margin 等，得到表格可用高度；若 ref 未就绪则回退为 `window.innerHeight - 120`。窗口 resize 或分页显隐时重新计算。采用「内层容器 + :height="100%"」后，表格高度由布局 100% 传递，无需再传 `tableHeight` 给表格。

### 4.2 首页布局（HomeView.vue）

- **.tab-content**
  - 增加 `min-height: 0`、`display: flex`、`flex-direction: column`，使高度能向子节点传递。
- **.tab-content > \***
  - 为路由出口内的页面根节点设置：`flex: 1 1 0`、`min-height: 0`、`overflow: hidden`，使列表（及其他 tab 页面）占满 tab 内容区且不溢出，从而列表的 `height: 100%` 有据可依。

## 五、关键 CSS 说明

| 属性 | 作用 |
|------|------|
| `height: 100%` | 列表根节点占满父级给定高度，与父级 flex 分配一致。 |
| `min-height: 0` | Flex 子项默认 `min-height: auto` 会按内容撑高；设为 0 后子项可被压缩，表格区才能只占「剩余空间」而不把分页顶出去。 |
| `flex: 1 1 0` | 表格区参与伸缩、从 0 起分配剩余空间，避免因内容过多而无限增高。 |
| `flex: 0 0 auto` | 头部和分页不伸缩，保持固定高度。 |
| `overflow: hidden` | 列表和表格区域不产生整页滚动，滚动仅发生在表格内部。 |
| `.table-area-inner` + `height: 100%` | 内层承接表格区域高度，表格用 `:height="100%"` 填满，保证 100% 链传到 `.el-scrollbar__wrap`。 |
| `.el-scrollbar__wrap` 的 `overflow-y: auto !important` | 确保实际可滚元素为 wrap，滚轮与拖拽滚动条均生效。 |

---

## 六、效果与小结

- 列表整体不超出当前 tab 内容区，不出现整页纵向滚动。
- 头部、表格、分页在同一屏内：头部在上，分页在下，表格在中间且可内部滚动。
- 表格高度随窗口或父容器变化由 100% 链传递，适配不同分辨率与布局。
- 分页始终固定在列表底部、在视口内可见可点击。
- **表格内部**：纵向滚动条可见且可拖拽、滚轮滚动表体均正常（仅 `.el-scrollbar__wrap` 滚动）。

**核心思路**：用「父级传递高度 + 列表 100% 继承 + 内部 flex 三分区 + 表格区 min-height:0 与 overflow」保证「整页不滚动、分页始终在屏内」；用「表格外增加内层容器 + 表格 :height="100%" + 不对 .el-table 做 flex 覆盖 + wrap 为唯一滚动容器」保证「仅表格内部滚动且滚轮/拖拽均生效」。
