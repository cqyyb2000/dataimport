# 账套信息表设计说明

本文档依据 **GB/T 24589.2-2010**（财经信息技术 会计核算软件数据接口 第2部分：行政事业单位）中的**电子账簿**数据元素，并结合项目 PRD、技术方案，设计系统**账套信息表**，用于多单位、多账套的独立管理与数据引入。

**设计原则**：账套主表与 XML `<电子账簿>` 结构一一对应，**会计年度单独分离**，与账套表呈**主从关系**（一账套对应多年度）。

---

## 一、XML 电子账簿结构与表对应关系

### 1.1 标准 XML 示例

```xml
<电子账簿>
  <电子账簿编号>XZ001</电子账簿编号>
  <电子账簿名称>行政账</电子账簿名称>
  <会计核算单位>残联本级</会计核算单位>
  <组织机构代码>009277399</组织机构代码>
  <单位类型>行政单位</单位类型>
  <行业></行业>
  <行政区划代码></行政区划代码>
  <预算管理级次>一级预算单位</预算管理级次>
  <经费来源>全额拨款</经费来源>
  <开发单位>北京用友政务软件有限公司</开发单位>
  <版本号>V6.6</版本号>
  <本位币>人民币元</本位币>
  <会计年度>2021</会计年度>
  <标准版本号>1.0</标准版本号>
</电子账簿>
```

### 1.2 数据结构划分

| 存放位置 | XML 元素 | 说明 |
|----------|----------|------|
| **主表 account_book** | 电子账簿编号、电子账簿名称、会计核算单位、组织机构代码、单位类型、行业、行政区划代码、预算管理级次、经费来源、开发单位、版本号、本位币、标准版本号 | 账套基本信息，**不含会计年度** |
| **从表 account_book_fiscal_year** | **会计年度** | 会计年度单独分离，与账套主从关系（一账套多年度） |

主表存一条账套即对应一个“电子账簿”单位；该账套下有哪些会计年度（如 2021、2022）全部存在从表中，通过 `account_book_code` 外键关联。

## 三、表结构概览（主从关系）

### 3.1 主表 account_book（账套信息）

与 XML `<电子账簿>` 一一对应，**不含会计年度**。

| 类别 | 字段数 | 说明 |
|------|--------|------|
| 主键与标准字段 | 13 | 电子账簿编号、名称、会计核算单位、组织机构代码、单位类型、行业、行政区划代码、预算管理级次、经费来源、开发单位、版本号、本位币、标准版本号 |
| 可选 | 1 | 默认会计年度（仅用于界面默认展示，数据在从表） |
| 系统维护 | 4 | 备注、状态、创建时间、更新时间 |

### 3.2 从表 account_book_fiscal_year（账套—会计年度，主从关系）

**会计年度单独分离**，一条主表账套对应多条从表年度记录。

| 字段 | 说明 |
|------|------|
| account_book_code | 账套编码（外键 → account_book，主从关联） |
| fiscal_year | 会计年度（4 位整数） |
| created_at | 首次导入该年度的时间 |

主键：`(account_book_code, fiscal_year)`；外键：`account_book_code` → `account_book(account_book_code)`，删除账套时从表级联删除。

## 五、数据类型与约束

- **字符型**：UTF-8，长度按上表，与标准一致。
- **数值型**：会计年度为 4 位整数（如 2021）。
- **主键**：账套主表 `account_book_code`；关联表 `(account_book_code, fiscal_year)`。
- **必填**：账套编码、账套名称、会计核算单位、单位类型、本位币、标准版本号。

---

## 六、与导入数据的匹配规则

导入 SHARE.xml 时：

1. 以 XML 中**电子账簿编号**匹配本表 **account_book_code**；若无则按**导入时账套校验规则**处理（见下文）。
2. **会计核算单位**应与账套的 **accounting_entity** 一致（PRD：电子账簿信息必须与账套信息匹配）。
3. 导入成功后，向 **account_book_fiscal_year** 插入一条记录（账套编码 + 会计年度），若已存在则忽略；并可更新 **default_fiscal_year**（若业务需要）。

## 六（补充）、导入时账套校验规则（基本信息 XML 无对应账套时如何验证）

引入公共档案类 XML（如 SHARE.xml）时，若账套信息表中**没有**与 XML 中电子账簿对应的账套，可按下列规则做校验与处理。

### 5.1 校验前置条件

- **必须明确目标账套**：导入前由用户选择“目标账套编码”，或由系统用 XML 中的**电子账簿编号**作为目标账套编码去查找。
- 若业务要求“仅允许导入到已存在的账套”，则**不允许**在导入时自动建账套，未找到即校验不通过。

### 5.2 校验流程（推荐顺序）

1. **解析 XML**  
   从根节点下读取 `<电子账簿>`，取出：
   - 电子账簿编号（必填）
   - 会计核算单位（必填）
   - 会计年度（必填）
   - 其余标准字段（按需）

2. **确定目标账套编码**  
   - 若接口要求“上传时选择目标账套”：以**用户选择的账套编码**为准。  
   - 若接口为“仅根据文件内容导入”：以 XML 中的**电子账簿编号**作为目标账套编码。

3. **查找账套**  
   在 **account_book** 表中按 `account_book_code = 目标账套编码` 查询。

4. **根据“是否存在账套”分支**  
   - **存在账套**  
     - 校验 XML 中**会计核算单位**与账套 **accounting_entity** 是否一致（去除首尾空格后比较）。  
     - 不一致 → **校验不通过**，提示：“电子账簿信息与所选账套不一致：会计核算单位【XML 值】与账套【账套值】不符。”  
     - 一致 → 继续后续业务校验（年度、档案数据等），通过则执行导入。  
   - **不存在账套**  
     - 若系统**不支持**“按 XML 自动建账套”：  
       → **校验不通过**，提示：“未找到账套【目标账套编码】，请先在账套管理中创建该账套后再导入，或使用‘按 XML 自动建账套’方式导入。”  
     - 若系统**支持**“按 XML 自动建账套”（由配置或接口参数控制）：  
       → 使用 XML 中 `<电子账簿>` 的必填/选填字段，在 **account_book** 中**先插入一条新账套**，再按“存在账套”的规则校验**会计核算单位**（此时必然一致），通过后继续导入；若插入失败（如唯一约束冲突）则按“不存在账套”的报错方式提示。

5. **导入成功后**  
   按前文“与导入数据的匹配规则”，维护 **account_book_fiscal_year** 等。

### 5.3 两种策略小结

| 策略 | 账套不存在时的行为 | 适用场景 |
|------|--------------------|----------|
| **仅导入到已有账套** | 校验不通过，明确提示“未找到账套【xxx】，请先创建账套或使用自动建账套” | 严格先建账套、后导入，便于统一管理 |
| **允许按 XML 自动建账套** | 用 XML 中电子账簿信息创建新账套，再校验并导入 | 首次引入、希望减少手工建账套操作 |

### 5.4 建议的校验错误码/提示（便于接口与前端）

- `ACCOUNT_BOOK_NOT_FOUND`：未找到账套【{account_book_code}】，请先在账套管理中创建该账套后再导入。
- `ACCOUNTING_ENTITY_MISMATCH`：电子账簿信息与账套不一致：会计核算单位【{xml_value}】与账套【{db_value}】不符，请确认文件与所选账套对应同一单位。
- `MISSING_ELECTRONIC_ACCOUNT_BOOK`：XML 中缺少有效的电子账簿信息，无法确定目标账套。

实现时：先解析 XML 得到电子账簿编号与会计核算单位，再查 account_book；若无对应账套且不允许自动建账套，则直接返回 `ACCOUNT_BOOK_NOT_FOUND`，不写入任何数据。

## 八、扩展说明

- **已导入年度**：由独立关联表 **account_book_fiscal_year** 维护，便于按年度统计、权限控制及与导入历史等表关联。
- **会计年度**：标准电子账簿中“会计年度”表示该份导出数据所属年度；关联表记录该账套下已存在的年度集合，**default_fiscal_year** 仅用于界面默认年度。
