# 宣传部报销台账需求分析

**状态**：已与需求方逐项确认  
**日期**：2026-11-12  
**依据**：`报销台帐/基本需求.md`  
**范围**：在当前会计核算数据引入平台中新增宣传部报销台账。本文记录已经确认的业务规则，供后续设计和开发使用。

---

## 1. 结论

宣传部使用一套报销台账。台账按年度工作。部门、项目、预算、报销单都由本模块自己维护。部门和项目都是多级档案。

会计录入报销单，保存后为待支出。出纳确认后才计入支出。当前余额 = 该年度该部门该项目的预算金额 − 已计入金额。余额可以为负数。

一天、一月、一年的支出总额在报销明细中按报销时间筛选后查看，并且只统计已计入。单位报销统计按所选年度列出全部预算，按部门或按项目汇总，并可以点进明细。

---

## 2. 和现有系统的关系

台账做在当前 Flask + Vue 应用里，共用登录、菜单、权限和 MySQL。

本模块不使用账套。现有的内设机构、项目档案仍只服务于会计核算数据引入，按账套和会计年度存放。报销台账的部门、项目不读取、不回写这两类档案，也不生成总账凭证。

用户表目前只有管理员标记和菜单权限，没有角色。非管理员要在用户管理中选定一个角色：会计或出纳。管理员沿用现有管理员标记，报销台账的两类操作都可以做。

金额按人民币记录，保留两位小数。

## 3. 角色、菜单和页面

一级菜单名称为「报销台账」，下面五个页面：

| 页面 | 会计 | 出纳 | 管理员 |
| --- | --- | --- | --- |
| 部门与项目 | 可维护 | 不可进入 | 可维护 |
| 预算 | 可维护 | 不可进入 | 可维护 |
| 报销录入 | 可录入、修改、删除待支出 | 不可进入 | 可录入、修改、删除待支出 |
| 报销明细 | 可查看、筛选、导出；可进入待支出的修改和删除 | 可查看、筛选、导出；可确认计入和取消确认 | 两类操作都可以 |
| 单位报销统计 | 可查看、筛选、导出、穿透 | 可查看、筛选、导出、穿透 | 可以 |

进入报销台账后先选定年度。五个页面都只处理这一年。

## 4. 部门与项目

部门和项目按年度建立，并且各自形成一棵多级树。部门的上级只能是部门，项目的上级只能是项目。同一年度内部门代码唯一，项目代码唯一。

每一条档案包含上级代码和级次：

- 没有上级的为第一级，级次为 1。
- 有上级时，上级必须是同一年度、同一类档案中已经存在的记录。级次 = 上级级次 + 1。
- 不能把本级或本级的下级设为上级，不能形成循环。
- 不预设层数上限。
- 上级可以调整。调整后，本级和全部下级的级次按新上级重算。
- 已有预算或报销单的部门、项目，不能再增加下级，也不能把其他档案调整到它下面。下级全部删除后，它重新成为最明细级。

「部门与项目」页面按这个层级展示。最明细级是当前没有下级的那一条。

保存之后：

- 代码不能修改。
- 当前没有任何报销单引用时，可以修改名称。只出现在预算里、还没有报销单时，也可以改名。
- 待支出和已计入都算被报销单使用。被使用后不能改名。这些报销单全部删除之后，可以再改名。
- 被预算或报销单使用过的部门、项目不能删除。
- 下面还有下级的部门、项目不能删除。

报表和单据展示该年度档案中的当前名称。名称一旦被报销单锁定，展示名称就保持不变。

---

## 5. 预算

一条预算由「年度 + 部门 + 项目」唯一确定。金额是该年度这个组合的预算额度。年中追加预算时，直接修改这一条的金额，不新增第二条。

- 预算只能选择同一年度、并且都是最明细级的部门和项目。有下级的部门、项目不能建立预算。
- 年度、部门、项目保存后不能改，只能改金额。要换成别的部门或项目时，删除后重建。
- 预算金额大于等于 0，保留两位小数。
- 没有报销单的预算可以删除。
- 已经有报销单的预算不能删除，但可以修改金额。
- 把预算改到低于已计入金额时直接保存，余额为负。修改预算不弹超支窗。

报销单只能选择本年度已经建好的预算，因此部门和项目也都是最明细级。没有对应预算时，不能保存报销单。表单上选择部门、项目，或直接选择预算，指向的是同一条预算。选择时只列出最明细级。

---

## 6. 报销单

一张报销单只有一笔金额。手填项为报销时间、报销人、摘要、报销金额。

| 项 | 规则 |
| --- | --- |
| 报销时间 | 精确到日期，可以是所选年度中的任意一天，年份必须等于所选年度 |
| 报销人 | 必填，手填文本，不必是系统用户 |
| 摘要 | 必填 |
| 报销金额 | 大于 0，保留两位小数 |
| 单据号 | 系统生成，用户不手填 |
| 附件 | 不上传 |

状态只有两个：

| 状态 | 含义 | 谁可以改变 |
| --- | --- | --- |
| 待支出 | 会计已保存，尚未计入支出 | 出纳确认后变为已计入；会计可以修改和删除 |
| 已计入 | 出纳已确认，计入支出和余额 | 出纳取消确认后回到待支出 |

确认支出叫计入。没有确认的叫待支出。没有单独的审批流，也没有作废状态。

已计入的单据不能修改金额、摘要、部门、项目、报销人和报销时间，也不能删除。要修改或删除时，先由出纳取消确认，回到待支出后，再由会计处理。

删除待支出后，单据不保留。

出纳在报销明细中操作。未超支时，单击确认就计入。只有会让余额变成负数时，才弹出提醒。

---

## 7. 余额与超支

当前余额 = 预算金额 − 该预算下已计入金额。

待支出不参与余额，也不参与每天、每月、每年的支出总额。

超支判断使用：已计入合计 + 本次金额 > 预算金额。其他待支出不计入这次比较。

会计保存、以及出纳确认计入时，都做这个判断。

- 不会超支：直接完成。会计保存后仍是待支出，余额不变。出纳确认后变为已计入，余额立即减少。
- 会超支：弹出提醒，按钮为「取消」和「保存」。取消则这次操作不生效。保存则继续。出纳确认保存后，余额可以为负数。

会计保存时的提醒是提前告知。这次保存本身不把金额计入余额。真正减少余额的动作是出纳确认。

---

## 8. 单据号

单据号为四位年、两位月、四位流水号，例如 `2026050003`。

- 年月取报销时间，不取录入当天。
- 流水号在该年月内从 `0001` 递增，每月各自编号。
- 每个年月记录已经发出的最大流水号。删除单据，或待支出改到别的月份而放弃原号时，最大流水号不减小，号码不回收。
- 待支出仍在同一个月份内修改报销时间时，单据号不变。
- 待支出改到别的月份时，按新月份重新取号。单据只保留新号，旧号不保留，也不能再按旧号查询。
- 已计入不能修改报销时间，单据号保持不变。
- 当月流水号超过 `9999` 时，拒绝保存。

---

## 9. 从其他年度复制

会计在「部门与项目」中发起复制，选择来源年度。一次复制来源年度的部门、项目和预算金额。来源年度的报销单留在来源年度。

复制后，代码、名称、上级代码、级次和预算金额与来源年度相同，层级结构保持一致，之后按第 4、5 节的规则各自修改。

| 目标年度的情况 | 系统行为 |
| --- | --- |
| 没有部门、项目和预算 | 直接复制 |
| 已有部门、项目或预算，并且没有报销单 | 先提醒来源年度、目标年度，以及将删除的部门数、项目数、预算数。取消则停止。继续则先删除这三类，再写入复制结果。删除和复制同时成功，或同时不生效 |
| 还存在报销单 | 不删除、不复制。提示先处理报销单：待支出由会计删除；已计入先由出纳取消确认，再由会计删除 |

## 10. 报销明细

明细展示单据本身的字段，并作为录入之后的查看界面。

可按报销时间筛到日、月或年，也可按单据字段和状态筛选。状态筛选为待支出、已计入或全部。

在当前筛选结果上同时显示两个合计：

- 支出总额：其中已计入金额之和。每天、每月、每年的支出总额用这个筛选完成。
- 待支出合计：其中待支出金额之和。

导出 Excel 时，导出当前筛选结果，列与页面一致。页面列至少包括：单据号、报销时间、部门、项目、报销人、摘要、报销金额、状态。

---

## 11. 单位报销统计

统计只汇总所选年度全年，不再按月、日切开。月和日的总额只在明细中查看。预算和报销单都在最明细级，统计按预算上的部门和项目汇总。

列出该年度的每一条预算。还没有报销单的行，已计入和待支出为 0，余额等于预算金额。

每一行展示：

| 列 | 计算 |
| --- | --- |
| 预算金额 | 该预算的金额 |
| 已计入 | 该预算下已计入报销金额之和 |
| 待支出 | 该预算下待支出报销金额之和 |
| 余额 | 预算金额 − 已计入，可以为负数 |

汇总方式有两种：

- 按部门：先显示部门小计，下面是该部门的各个项目。
- 按项目：先显示项目小计，下面是该项目的各个部门。

点击已计入金额，打开该范围内的已计入明细。点击待支出金额，打开该范围内的待支出明细。部门或项目小计上的金额，打开该小计范围内的对应明细。穿透时带上所选年度。

导出 Excel 时，导出当前汇总结果，列与页面一致。

## 12. 数据对象

实现时使用本模块自己的表。下面是逻辑对象，不是最终表结构。

**部门**

- 年度、部门代码、部门名称、上级部门代码、级次
- 同一年度部门代码唯一
- 上级部门代码为空时，级次为 1；有上级时，上级必须是同一年度的部门

**项目**

- 年度、项目代码、项目名称、上级项目代码、级次
- 同一年度项目代码唯一
- 上级项目代码为空时，级次为 1；有上级时，上级必须是同一年度的项目

**预算**

- 年度、部门代码、项目代码、金额
- 同一年度、同一部门、同一项目只有一条
- 部门和项目必须属于同一年度，并且都是当时的最明细级

**报销单**

- 单据号、年度、报销时间、部门代码、项目代码、报销人、摘要、金额、状态
- 状态为待支出或已计入
- 部门、项目、年度必须对应一条仍存在的预算
- 单据号全局唯一

**年月流水**

- 年度、月份、已发出的最大流水号
- 只增不减

**用户**

- 在现有用户上增加角色，字段名为 `role`
- 取值：`accountant` 表示会计，`cashier` 表示出纳
- 非管理员每人一个角色；管理员不依赖这个字段，保持为空

物理表与模型对应如下。最明细级、禁止循环、流水号只增不减仍由后续服务层校验；外键保证上级、预算和报销单的引用不能悬空。

| 表 | 模型 | 说明 |
| --- | --- | --- |
| `bx_department` | `BxDepartment` | 年度 + 部门代码 |
| `bx_project` | `BxProject` | 年度 + 项目代码 |
| `bx_budget` | `BxBudget` | 年度 + 部门 + 项目 |
| `bx_claim` | `BxClaim` | 报销单，单据号全局唯一，状态取「待支出」「已计入」 |
| `bx_doc_seq` | `BxDocSeq` | 每个年月已发出的最大流水号 |
| `users.role` | `User.role` | 在原用户表上增加，不新建用户表 |

## 13. 实现落点

后端沿用现有 Flask 蓝图、SQLAlchemy 和 `/api` 接口风格。前端沿用现有布局、菜单和路由方式。

报销台账新建的代码文件，都放在原有代码目录下新建的 `bx` 子目录中，不与会计核算引入的代码混放。

| 原有目录 | 报销台账代码目录 |
| --- | --- |
| `backend/Model` | `backend/Model/bx` |
| `backend/routes` | `backend/routes/bx` |
| `backend/services` | `backend/services/bx` |
| `backend/tests` | `backend/tests/bx` |
| `backend/数据库脚本` | `backend/数据库脚本/bx` |
| `frontend/src/views` | `frontend/src/views/bx` |
| `frontend/src/api` | `frontend/src/api/bx` |
| `frontend/src/components` | `frontend/src/components/bx` |

以后如果还在别的代码目录里为本模块新增文件，同样在该目录下建 `bx` 再保存。需求说明本身仍放在 `backend/报销台帐`，不移入 `bx`。

接入现有应用时要改动的原有文件留在原处，包括：`app.py` 注册蓝图，用户模型增加角色，登录结果返回角色，路由入口登记五个页面，菜单表增加「报销台账」及其子菜单。

接口权限：出纳不能调用部门、项目、预算和报销录入的维护接口。会计不能调用确认计入和取消确认接口。管理员两类接口都可以调用。

超支判断、余额、单据号和年度复制放在 `services/bx` 中完成。页面上的合计只用于展示，以服务端计算结果为准。

## 14. 本次不做

- 不上传报销附件。
- 不生成会计核算凭证，不改账套档案。
- 不做多币种。
- 不增加作废、停用或第二级审批。
- 统计报表不按月、按日再切。
- 不把来源年度的报销单复制到目标年度。
