# GL.xml 凭证导入问题修复说明

## 问题描述

用户上传GL.xml后，凭证数据没有写入数据库。经检查发现，实际GL.xml文件中的凭证数据结构与标准文档不同：

### 标准格式（文档定义）
```xml
<记账凭证>
  <凭证编号>0001</凭证编号>
  <凭证日期>20210101</凭证日期>
  <会计年度>2021</会计年度>
  <会计期间号>1</会计期间号>
  ...
</记账凭证>
<记账凭证分录行>
  <凭证编号>0001</凭证编号>
  <分录行号>1</分录行号>
  <科目编号>1001</科目编号>
  ...
</记账凭证分录行>
```

### 实际格式（扁平化结构）
```xml
<记账凭证>
  <记账凭证日期>20210131</记账凭证日期>
  <会计年度>2021</会计年度>
  <会计期间号>1</会计期间号>
  <记账凭证类型编号>JZ</记账凭证类型编号>
  <记账凭证编号>JZ-01-0001</记账凭证编号>
  <记账凭证行号>24</记账凭证行号>
  <记账凭证摘要>...</记账凭证摘要>
  <科目编号>60010101</科目编号>
  <辅助项1编号>001</辅助项1编号>
  <辅助项2编号>2081101</辅助项2编号>
  <借方本币金额>0.00</借方本币金额>
  <贷方本币金额>650400.00</贷方本币金额>
  ...
</记账凭证>
```

**关键差异**：
1. 每个`<记账凭证>`元素包含凭证头和分录行的所有信息
2. 字段名不同（如"记账凭证日期"而非"凭证日期"）
3. 使用"记账凭证行号"而非"分录行号"
4. 使用"借方本币金额"/"贷方本币金额"而非"借方金额"/"贷方金额"
5. 辅助项使用"辅助项1编号"、"辅助项2编号"等格式

## 修复方案

### 1. 更新 `import_vouchers()` 函数

**改进点**：
- 支持两种字段名格式（标准格式和扁平格式）
- 使用集合去重，避免同一凭证重复创建（扁平格式中同一凭证有多条记录）
- 支持从"记账标志"和"作废标志"推断凭证状态

**字段映射**：
| 标准字段名 | 扁平格式字段名 | 说明 |
|-----------|--------------|------|
| 凭证编号 | 记账凭证编号 | 凭证编号 |
| 凭证日期 | 记账凭证日期 | 凭证日期 |
| 附单据数 | 附件数 | 附件数量 |
| 凭证状态 | 记账标志+作废标志 | 推断状态 |

### 2. 更新 `import_voucher_entries()` 函数

**改进点**：
- 优先使用标准格式的"记账凭证分录行"类别
- 如果没有标准格式，则从"记账凭证"类别中提取分录行信息
- 支持多种字段名格式
- 支持辅助项1-30编号的解析

**字段映射**：
| 标准字段名 | 扁平格式字段名 | 说明 |
|-----------|--------------|------|
| 凭证编号 | 记账凭证编号 | 凭证编号 |
| 分录行号 | 记账凭证行号 | 分录行号 |
| 摘要 | 记账凭证摘要 | 分录摘要 |
| 借方金额 | 借方本币金额 | 借方金额 |
| 贷方金额 | 贷方本币金额 | 贷方金额 |
| 原币借方金额 | 借方原币金额 | 原币借方金额 |
| 原币贷方金额 | 贷方原币金额 | 原币贷方金额 |
| 数量 | 借方数量/贷方数量 | 数量 |
| 辅助项编号 | 辅助项1编号~辅助项30编号 | 辅助项编号 |

### 3. 处理逻辑

**凭证头导入**：
1. 遍历所有"记账凭证"元素
2. 提取凭证头信息（凭证编号、日期、类型等）
3. 使用集合去重，每个凭证编号+期间号只创建一次凭证头
4. 如果凭证已存在，则更新信息

**分录行导入**：
1. 优先检查是否有"记账凭证分录行"类别
2. 如果没有，则从"记账凭证"类别中提取
3. 每个"记账凭证"元素创建一条分录行记录
4. 使用"记账凭证行号"作为分录行号

## 测试建议

### 1. 测试扁平格式导入
- 上传包含扁平格式凭证的GL.xml文件
- 验证凭证头是否正确创建（每个凭证编号只创建一次）
- 验证分录行是否正确创建（每个记账凭证行号创建一条记录）

### 2. 测试标准格式导入
- 上传包含标准格式凭证的GL.xml文件
- 验证凭证头和分录行是否正确分离

### 3. 测试混合格式
- 如果XML中同时包含两种格式，验证是否能正确处理

## 注意事项

1. **凭证去重**：扁平格式中，同一凭证的多条分录行会重复包含凭证头信息，需要使用集合去重
2. **字段名兼容**：代码同时支持标准字段名和扁平格式字段名
3. **辅助项映射**：辅助项1-30编号需要根据实际业务规则映射到具体的辅助核算字段（单位往来、项目等）
4. **数据完整性**：确保先创建凭证头，再创建分录行（外键约束）
